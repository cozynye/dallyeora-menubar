# 사용성 정리: 설계 스펙

작성일: 2026-11-13
기반: `docs/spec.md`, `docs/spec-cleanup.md` (v0.5.0 시점의 앱)
목표 버전: 0.6.0

## 1. 목적

v0.5.0을 쓰면서 걸리는 지점 여덟 가지를 고친다. 로그인할 때 자동으로 켜려면 터미널 명령을 쳐야 하고, 메뉴 막대에서 숫자를 볼 방법이 없고, 화면이 꺼져 있어도 계속 그리며, 정리하기 창은 프로세스를 확인 없이 죽이고 줄이 2초마다 움직여 버튼을 잘못 누르기 쉽다. 기능을 손대는 김에 `StatusItemController`에 몰려 있는 책임도 나눈다.

## 2. 범위

### 포함
1. 메뉴의 "로그인 시 실행" 항목
2. 메뉴의 "메뉴 막대에 사용률 표시" 항목
3. 화면이 꺼지거나 세션이 비활성일 때 타이머 정지
4. 펼친 프로세스 종료 전 확인 창
5. 정리하기 창과 메뉴 막대의 지표 공유
6. 마우스가 목록 위에 있는 동안 줄 순서 고정
7. 종료 결과를 알려 주는 상태 줄
8. 정리하기 창의 검색 칸(⌘F)과 전역 단축키 ⌃⌥⌘D
9. `StatusItemController` 분리와 설정 변경 알림
10. 새 버전 알림 (하루 한 번 확인, 메뉴에 표시)

### 제외
- CPU와 메모리를 메뉴에 함께 보여 주기 (필요 없다고 결정)
- 일반 "종료" 버튼의 확인 창 (⌘Q와 같은 요청이라 저장할 것이 있으면 그 앱이 묻는다)
- 단축키를 바꾸는 UI, 영어 UI, 창 하나만 닫기
- 새 버전을 내려받아 설치하는 자동 업데이트 (Sparkle을 쓰면 서명 키와 appcast 관리가 따라와서 알림만 한다)

## 3. 동작

### 3.1 메뉴
```
새 버전 0.7.0 받기          (새 버전을 알 때만)
───────────────
개복치                 CPU 42%
스트레스로 위독
───────────────
정리하기…                ⌃⌥⌘D
───────────────
캐릭터 ▸ / 말투 ▸ / 지표 ▸
메뉴 막대에 대사 표시
메뉴 막대에 사용률 표시
로그인 시 실행
새 버전 자동 확인
───────────────
종료                       ⌘Q
```

### 3.2 로그인 시 실행
`SMAppService.mainApp`으로 등록하고 해제한다. 체크 상태는 앱이 저장하지 않고 메뉴를 열 때마다 `status == .enabled`인지 읽어서 정하므로, 시스템 설정에서 사용자가 직접 끈 경우에도 맞게 보인다. 등록이나 해제가 실패하면 오류 문구를 `NSAlert`로 보여 주고, 상태가 `.requiresApproval`이면 시스템 설정의 로그인 항목 화면을 연다. 실행 파일이 `.app` 번들 안에 있지 않으면(`swift run`) 항목을 비활성화한다.

### 3.3 사용률 표시
설정 `showsPercent`(기본 꺼짐)를 추가한다. 메뉴 막대 글자는 아래 네 가지 중 하나다.

| 사용률 표시 | 대사 보임 | 글자 |
|---|---|---|
| 꺼짐 | 아니오 | (없음) |
| 켜짐 | 아니오 | ` 42%` |
| 꺼짐 | 예 | ` 스트레스로 위독` |
| 켜짐 | 예 | ` 42% 스트레스로 위독` |

"대사 보임"은 지금과 같이 대사 표시를 켰거나 단계가 바뀌어 3초 동안 보여 주는 중일 때다. 숫자는 고정폭 숫자 글꼴로 그리고 폭은 ` 100%` 기준으로 잡아 값이 바뀌어도 옆 아이콘이 밀리지 않게 한다. 대사 폭 상한 150pt는 대사에만 적용하고 숫자 폭은 그 위에 더한다.

### 3.4 화면이 꺼지면 멈춤
`NSWorkspace`의 `screensDidSleep`/`screensDidWake`, `sessionDidResignActive`/`sessionDidBecomeActive` 알림을 듣는다. 화면이 잠들었거나 세션이 비활성이면 측정 타이머와 그리기 타이머를 모두 끊고, 둘 다 풀리면 한 번 측정한 뒤 다시 건다. 정리하기 창이 열려 있으면 그 갱신도 같이 멈췄다가 다시 돈다. 정리하기 창은 Dock으로 최소화한 동안에도 갱신을 멈추고, 꺼내면 다시 돈다. 멈춘 동안의 CPU tick 차이는 첫 측정에서 한 번 평균으로 잡히는데, 지금도 2초 평균이라 따로 버리지 않는다.

### 3.5 정리하기 창
```
[CPU | 메모리]                         [검색 칸]
지금 메모리를 많이 쓰는 것 · 전체 85%
┌──────────────────────────────────────────┐
│ 목록                                       │
└──────────────────────────────────────────┘
종료했습니다: Slack
```

지표. 세그먼트 컨트롤은 `Settings.metric`을 그대로 읽고 쓴다. 창에서 바꾸면 메뉴 막대 캐릭터도 그 지표를 따르고, 메뉴에서 바꾸면 열려 있는 창도 바뀐다. `spec-cleanup.md` 3.3의 "여기서 바꿔도 메뉴 막대 지표나 설정은 바뀌지 않는다"는 이 스펙으로 대체한다.

검색. 오른쪽 위의 검색 칸에 입력하면 줄의 제목, 설명, 묶인 프로세스 이름 중 하나에 그 글자가 들어 있는 줄만 남긴다. 대소문자는 구분하지 않고 앞뒤 공백은 무시하며, 빈 검색어는 전부 보여 준다. ⌘F로 검색 칸에 포커스가 가고 Esc로 검색어를 지운다. 맞는 줄이 없으면 목록 자리에 "'검색어'에 맞는 항목이 없습니다"를 보여 준다. 검색어는 창을 닫으면 비운다.

줄 고정. 마우스가 목록 위에 올라가는 순간의 줄 순서와 각 줄 안의 프로세스 순서를 기억하고, 마우스가 올라가 있는 동안에는 그 순서를 유지한 채 숫자와 버튼 상태만 갱신한다. 그사이 새로 생긴 줄은 사용량 순으로 맨 아래에 붙고 사라진 줄은 빠진다. 마우스가 목록을 벗어나면 바로 사용량 순으로 다시 정렬한다. 지표를 바꾸면 기억한 순서를 버린다.

프로세스 종료 확인. 펼친 프로세스의 "종료"를 누르면 `NSAlert`를 띄운다. 제목은 `"<이름>"(pid <번호>)을(를) 끌까요?`, 설명은 `이 앱의 탭이나 창, 확장 같은 일부가 깨질 수 있습니다.`, 버튼은 "종료"와 "취소"다. 강제 종료 확인 창은 그대로 둔다.

상태 줄. 창 맨 아래 한 줄에 마지막 결과를 5초 동안 보여 주고 지운다. 새 결과가 오면 바꿔 쓰고 시간을 다시 센다. 종료를 요청해 둔 채 창을 닫으면 그 요청은 잊고, 다시 열었을 때 버튼은 "종료"로 돌아가 있으며 결과를 뒤늦게 알리지 않는다.

| 상황 | 문구 |
|---|---|
| 종료를 요청한 앱이 목록에서 사라짐 | `종료했습니다: <앱>` |
| 종료 요청을 보내지 못함 | `종료 요청을 보내지 못했습니다: <앱>` |
| 10초가 지나도 살아 있음 | `응답이 없어 강제 종료 버튼으로 바꿨습니다: <앱>` |
| 강제 종료함 | `강제 종료했습니다: <앱>` |
| 강제 종료 요청이 실패함 | `강제 종료하지 못했습니다: <앱>` |
| 프로세스 하나가 0.5초 뒤 사라짐 | `종료했습니다: <이름> (pid <번호>)` |
| 프로세스가 0.5초 뒤에도 살아 있음 | `종료를 요청했지만 아직 실행 중입니다: <이름> (pid <번호>)` |
| `kill`이 EPERM으로 실패 | `권한이 없어 끌 수 없습니다: <이름> (pid <번호>)` |
| `kill`이 ESRCH로 실패 | `이미 끝난 프로세스입니다: <이름> (pid <번호>)` |
| `kill`이 그 밖의 이유로 실패 | `끌 수 없습니다: <이름> (pid <번호>)` |

### 3.6 전역 단축키
Carbon `RegisterEventHotKey`로 ⌃⌥⌘D를 등록하고, 눌리면 메뉴의 "정리하기…"와 같은 동작을 한다. 이 API는 접근성 권한이 필요 없다. 등록에 성공했을 때만 메뉴 항목 옆에 단축키를 표시하고, 다른 앱이 이미 쓰고 있어 실패하면 표시 없이 메뉴로만 연다.

### 3.7 새 버전 알림
앱을 켤 때와 그 뒤 한 시간마다, 마지막 확인에서 24시간이 지났으면 `https://api.github.com/repos/cozynye/dallyeora-menubar/releases/latest`를 한 번 읽는다. 응답의 `tag_name`이 설치된 버전(`CFBundleShortVersionString`)보다 높으면 메뉴 맨 위에 `새 버전 <번호> 받기`가 생기고, 누르면 브라우저로 `https://github.com/cozynye/dallyeora-menubar/releases/latest`를 연다. 응답에 든 주소는 열지 않는다. 내려받기와 설치는 사용자가 한다.

마지막 확인 시각과 읽은 버전은 `UserDefaults`(`lastUpdateCheck`, `latestKnownVersion`)에 두어서 앱을 다시 켜도 알림이 남는다. 요청이 실패하거나 사용량 제한 응답처럼 번호를 읽을 수 없으면 시각을 적지 않고 다음 시간에 다시 시도한다. 버전은 숫자와 점으로만 된 것만 인정하고 `-beta` 같은 꼬리가 붙은 태그는 무시한다.

설정 `checksForUpdates`(기본 켜짐)를 메뉴의 "새 버전 자동 확인"으로 끌 수 있고, 끄면 요청을 보내지 않으며 이미 알고 있던 알림도 숨긴다. `swift run`처럼 번들 버전이 없으면 확인하지 않고 항목을 비활성화한다. 보내는 것은 일반적인 HTTPS 요청 하나이고 앱이나 기기를 식별하는 값은 붙이지 않는다.

## 4. 구조

### Core (`Sources/DallyeoraCore`, 테스트 대상)
- `Settings`: `showsPercent`를 추가하고, 값을 쓸 때마다 `Settings.didChange` 알림을 `NotificationCenter.default`에 보낸다(object는 그 `Settings`).
- `StatusTitle`: 사용률과 대사로 메뉴 막대 글자를 만든다. `text(percent: Double?, phrase: String?) -> String`.
- `StatusLayout.length`: 인자에 `percentWidth`를 추가한다. 상한은 대사 폭에만 건다.
- `ActivityState`: 화면 잠듦과 세션 비활성 두 플래그를 받아 지금 돌아야 하는지(`isActive`)와 그 값이 바뀌었는지를 알려 준다.
- `Update/AppVersion`: 릴리스 번호를 읽고 숫자로 비교한다.
- `Update/UpdateCheck`: 응답에서 태그 읽기, 확인할 때가 됐는지, 설치된 것보다 높은지.
- `Cleanup/RowFilter`: 검색어와 줄의 글자들을 받아 맞는지 판정한다.
- `Cleanup/StableOrder`: 새 순서와 기억한 순서를 받아 화면 순서를 만든다. 줄 id와 pid 양쪽에 쓰도록 제네릭으로 둔다.
- `Cleanup/CleanupNotice`: 3.5 표의 상황을 enum으로 두고 문구를 만든다.

### 앱 (`Sources/Dallyeora`)
- `StatusItemController`: 타이머와 그리기만 남긴다. `Settings.didChange`를 받으면 체크 표시, 폭, 그림을 한 번에 다시 맞추는 `apply()` 하나를 부르고, 메뉴 액션들은 설정만 바꾼다.
- `StatusMenu`: 메뉴 구성과 체크 표시, 액션을 맡는다.
- `LoginItem`: `SMAppService` 감싸기(`isAvailable`, `isEnabled`, `setEnabled`).
- `ActivityMonitor`: `NSWorkspace` 알림을 `ActivityState`에 넣고 바뀌면 콜백을 부른다.
- `GlobalHotKey`: Carbon 단축키 등록과 해제.
- `UpdateChecker`: 한 시간 타이머와 `URLSession` 요청, 결과 저장.
- `Cleanup/CleanupModel`: `Settings`를 받아 지표를 공유하고, 검색어, 마우스 올림 여부, 상태 줄을 가진다. 줄 만들기 뒤에 `StableOrder`와 `RowFilter`를 차례로 적용한다.
- `Cleanup/CleanupView`: 검색 칸, 목록의 `onHover`, 상태 줄을 추가한다.
- `Cleanup/CleanupWindowController`: 프로세스 종료 확인 창을 추가하고, `ActivityMonitor`의 신호로 갱신을 멈추고 다시 건다.
- `Cleanup/AppTerminator.terminateProcess`: 성공 여부 대신 실패 이유(EPERM, ESRCH, 그 외)를 돌려준다.

## 5. 테스트

Core에 단위 테스트를 붙인다. `StatusTitle`의 네 조합, `StatusLayout`의 숫자 폭 합산과 대사 상한, `Settings`의 `showsPercent` 기본값과 변경 알림, `ActivityState`의 플래그 조합과 전환, `RowFilter`의 대소문자·공백·빈 검색어·프로세스 이름 일치, `StableOrder`의 유지·추가·삭제, `CleanupNotice`의 문구, `AppVersion`의 읽기와 비교, `UpdateCheck`의 응답 해석과 확인 주기가 대상이다.

AppKit에 붙은 부분은 `scripts/make-app.sh`로 만든 앱에서 손으로 확인한다. 로그인 시 실행을 켜고 시스템 설정에 보이는지, 숫자를 켰을 때 옆 아이콘이 밀리지 않는지, 화면을 재웠다 깨운 뒤 다시 움직이는지, ⌃⌥⌘D로 창이 뜨는지, 마우스를 올린 동안 줄이 멈추는지, 프로세스 종료 확인과 상태 줄이 나오는지를 본다.

## 6. 한계

- 새 버전 알림은 메뉴를 열어야 보이고, 이 기능이 들어간 0.6.0보다 낮은 버전을 쓰는 사람에게는 가지 않는다.

- 단축키는 ⌃⌥⌘D로 고정이고 다른 앱과 겹치면 쓸 수 없다.
- 줄 고정은 마우스 기준이라 키보드로 목록을 움직일 때는 적용되지 않는다.
- 로그인 시 실행은 `.app`으로 설치한 경우에만 되고, 앱을 다른 경로로 옮기면 다시 켜야 할 수 있다.
- 상태 줄의 "종료했습니다"는 줄이 목록에서 사라진 것을 보고 판단하므로, 앱이 저장 확인 창을 띄운 채 기다리는 동안에는 10초 뒤 "응답이 없어…" 문구가 나온다.
